# Runbook 2: token byte microscope

Observe every causally admitted generated token and record its native token ID,
causal position, and exact piece bytes. Then reconstruct the generation output
from those events.

This experiment makes the token/text boundary inspectable without assuming
that one token piece is valid UTF-8.

Source:
[`token_byte_microscope.rs`](../../crates/runtime/examples/token_byte_microscope.rs)

## Inputs

- one caller-supplied local GGUF model;
- exact prompt text; and
- an explicit native backend feature.

## Run

```sh
cargo run --quiet -p logit-loom-runtime --example token_byte_microscope \
  --features vulkan -- \
  /path/to/model.gguf "Complete this byte-level fragment: caf" \
  | tee token-byte-microscope.json
```

The example admits the prompt and requests at most 16 generated tokens. Its
observer runs synchronously only after each selected non-terminal token has
been decoded into causal state.

## Inspect

List the observed sequence:

```sh
jq '.observed_tokens[] | {
  generation_index,
  causal_position,
  token,
  piece_hex
}' token-byte-microscope.json
```

Prove that concatenating the observed pieces reconstructs the exact generation
bytes:

```sh
jq -e '
  ([.observed_tokens[].piece_hex] | join(""))
  == .generation.bytes_hex
' token-byte-microscope.json
```

Compare event and receipt accounting:

```sh
jq -e '
  (.observed_tokens | length) == .generation.receipt.admitted_tokens
  and .observers[0].observed_tokens == .generation.receipt.admitted_tokens
  and .observers[0].observed_bytes == .generation.receipt.admitted_bytes
  and .observers[0].final_position == .generation.receipt.final_position
' token-byte-microscope.json
```

## Mechanical success criteria

- Event indices are consecutive from zero.
- Causal positions advance by one per observed token, beginning immediately
  after `generation.receipt.initial_position`.
- Concatenated `piece_hex` values exactly equal `generation.bytes_hex`.
- Observer token, byte, and final-position accounting agrees with the
  generation receipt.

An end-of-generation selection is terminal and is not admitted, returned in
the token list, or sent to the observer. Its token ID appears only in
`generation.receipt.finish`.

## Variations

- Use prompts likely to produce accented text, emoji, source code, or mixed
  scripts and compare token-piece boundaries.
- Save the reconstructed bytes with:

  ```sh
  jq -r '.generation.bytes_hex' token-byte-microscope.json \
    | xxd -r -p > generated.bin
  ```

- Add a second observer and verify that ordered fan-out reports identical
  positions and byte counts.
- Extend `TokenEvent` downstream with timestamps, counters, or application
  tags while retaining the exact byte field.

Whether a particular string uses one token or several is model-specific. The
runbook records that fact; it does not prescribe a tokenizer behavior.

## Failure diagnosis

- No observed tokens with `end_of_generation` means the model selected a
  terminal token before any causal admission. That is a valid empty result.
- A token limit of 16 is intentional. Increase the source constant only when a
  longer bounded trace is useful.
- Do not decode each `piece_hex` independently as UTF-8. Reconstruct the full
  byte sequence first, then decode only if the application expects valid text.

The example writes no files itself. Treat any retained generated bytes
according to the prompt and deployment's data-handling requirements.
