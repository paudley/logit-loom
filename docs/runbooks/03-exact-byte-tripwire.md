# Runbook 3: exact byte tripwire

Give generation one exact byte suffix and inspect where it stops. Matching is
performed over accumulated generated bytes, so a suffix may span several token
pieces.

This experiment distinguishes an exact post-admission byte stop from a token
limit or end-of-generation selection.

Source:
[`exact_byte_stop.rs`](../../crates/runtime/examples/exact_byte_stop.rs)

## Inputs

- one caller-supplied local GGUF model;
- exact prompt text;
- a stop suffix encoded as hexadecimal; and
- an explicit native backend feature.

`STOP_HEX` accepts 1 to 4,096 bytes. For example, `0a` is LF, `2e` is `.`, and
`0d0a` is CRLF. Hexadecimal allows the stop to contain arbitrary bytes without
shell or UTF-8 reinterpretation.

## Run

This trial asks the model to continue a list and uses LF as the tripwire:

```sh
cargo run --quiet -p logit-loom-runtime --example exact_byte_stop \
  --features vulkan -- \
  /path/to/model.gguf "A short numbered list:\n1." 0a \
  | tee exact-byte-tripwire.json
```

The model sees the backslash and `n` literally in the command above. Use shell
syntax such as `$'A short numbered list:\n1.'` only when an actual prompt
newline is intended.

The example requests at most 128 generated tokens. Stop bytes are retained in
the exact output because matching occurs after the selected token and its
piece have been admitted.

## Inspect

```sh
jq '{
  stop_bytes_hex,
  stop_selected,
  output_ends_with_stop,
  finish: .generation.receipt.finish,
  admitted_tokens: .generation.receipt.admitted_tokens,
  admitted_bytes: .generation.receipt.admitted_bytes
}' exact-byte-tripwire.json
```

If the tripwire fired, verify the terminal receipt and retained suffix:

```sh
jq -e '
  if .stop_selected then
    .generation.receipt.finish.kind == "stop_sequence"
    and .generation.receipt.finish.index == 0
    and .output_ends_with_stop
  else
    .generation.receipt.finish.kind != "stop_sequence"
  end
' exact-byte-tripwire.json
```

## Mechanical success criteria

- `stop_bytes_hex` exactly matches the normalized lowercase input bytes.
- When `stop_selected` is true, finish kind is `stop_sequence`, index is zero,
  and the output ends with the complete stop suffix.
- When it is false, the receipt records either `token_limit` or
  `end_of_generation`; the run remains bounded.
- Receipt byte and token counts describe causally admitted output, including
  the token whose piece completed the suffix.

The tripwire need not fire for every prompt. That is an observation about this
bounded generation, not a contract failure.

## Variations

- Try a multi-byte UTF-8 sequence, such as `e29883` for the UTF-8 encoding of
  `U+2603`, without assuming it aligns to one token.
- Use a multi-character ASCII delimiter such as `3c454e443e` (`<END>`).
- Change the prompt while keeping the same stop bytes, then compare only the
  mechanical finish and accounting.
- Extend the example to attach several declared stops and inspect the reported
  lowest matching index.

## Failure diagnosis

- Odd-length, empty, non-hexadecimal, or oversized `STOP_HEX` input is rejected
  before model loading.
- If the finish is `end_of_generation`, the model selected a terminal token
  before the suffix appeared.
- If the finish is `token_limit`, the suffix did not occur within 128 admitted
  tokens. Try a different prompt or suffix, or deliberately change the bound.
- A suffix is matched only against generated bytes, not prompt bytes.

The example writes no files itself. Remove the JSON report when it is no
longer useful.
