# Mechanical experiment runbooks

Eight runbooks take one text-token or diffusion-state question from
caller-supplied local artifacts to a structured mechanics report. The first
five are backend-compatible text experiments. The final three bind those
experiments to exact catalogued profiles and maintained adapters.

| Runbook | Question | Main surfaces |
| --- | --- | --- |
| [Fork and jolt](01-fork-and-jolt.md) | What happens when the same checkpoint is replayed with one ordered logit transform? | Checkpoints, full-vocabulary rank bias, pipeline receipts |
| [Token byte microscope](02-token-byte-microscope.md) | Do observer events reconstruct the exact admitted output bytes? | Post-admission observers, arbitrary bytes, causal positions |
| [Exact byte tripwire](03-exact-byte-tripwire.md) | At which admitted token does an exact byte suffix stop generation? | Byte stops, token boundaries, terminal receipts |
| [Causal circuit breaker](04-causal-circuit-breaker.md) | Can one observer trigger cancellation that another observes at the same safe boundary? | Observer ordering, cancellation, cooperative stops |
| [LoRA transplant](05-lora-transplant.md) | Can steering be applied, cleared, and bracketed by a deterministic checkpoint replay? | LoRA scopes, cleanup receipts, session health |
| [Qwen profile replay](06-qwen-profile-replay.md) | Does the pinned small text profile reproduce one exact checkpoint branch? | Catalog verification, accelerator placement, exact token replay |
| [MiniT2I image fork](07-minit2i-fork.md) | Does one direct-RGB checkpoint reproduce unchanged and then accept one bounded state operation? | Companion ABI, diffusion checkpoint, channel bias, image identities |
| [Krea 2 latent transplant](08-krea2-latent-transplant.md) | Does one pinned latent checkpoint reproduce unchanged and then accept one bounded channel operation? | Gated components, latent checkpoint, exact plan identity, image identities |

These are experiments in mechanics, not benchmarks. An output difference is
not evidence of improvement, and an unchanged output does not mean the
mechanism failed. The receipts, identities, exact bytes, positions, and
lifecycle actions define the mechanically testable result.

## Shared prerequisites

Every runbook requires:

- the repository's pinned Rust toolchain;
- exact local model artifacts supplied by the caller;
- an explicitly selected accelerator backend;
- accelerator placement accepted by the native runtime; and
- optionally, `jq` for the inspection commands.

Text runbooks select a `llama-cpp-4` Cargo feature such as `vulkan`, `cuda`, or
`metal`. Image runbooks build the exact versioned stable-diffusion.cpp
companion for `vulkan`, `hip`, `cuda`, or `metal`, then select one exact device
reported by that library. Shared accelerator use is fine.

The examples never download a model, choose a hidden prompt template, or retry
a rejected accelerator placement as CPU-only inference.

Run commands from the repository root. Each successful example writes one
pretty JSON document to standard output. Cargo errors and native diagnostics
remain on standard error, so this pattern leaves a reusable report:

```sh
cargo run --quiet -p logit-loom-runtime --example EXAMPLE \
  --features vulkan -- ARGUMENTS... | tee experiment.json
```

Reports include exact artifact/runtime identities, placement evidence, plans,
and receipts. Prompts and local paths are not copied into image reports.
General text experiments encode generated bytes as lowercase hexadecimal
because token pieces are not required to be UTF-8.

## Evidence boundary

Ordinary repository checks compile these examples but do not execute a model.
A live report therefore records one opt-in run on the caller's artifact and
deployment. It establishes that the reported mechanics ran for that execution;
it does not establish semantic correctness, generality, model quality, or
research efficacy.

Keep transient reports only when their prompts and resulting bytes are
suitable for the intended audience. A retained, output-free profile acceptance
projection follows
[`model-run.schema.json`](../acceptance/model-run.schema.json). The repository
does not require or collect generated output corpora.
